# Repetition Gate Evidence

This directory records the limited repeated-memory protection at runtime revision
`74ccb92`, compared with parent `aca468a`. It does not contain private transcripts,
event identifiers, session identifiers, raw replay datasets, embeddings, or claim
hashes. `replay-summary.json` is generated by the whitelist-only
`scripts/summarize_repetition_replay.rb` from the existing September 2 reports.

The replay uses historical design and confirmation-named splits already used in
development. It is a retrospective regression comparison, not new untouched
confirmation. The two session extractors used the historical August 28 cutoff;
the chat extraction used a fixed 86-page manifest. It is not every conversation
available by the replay date. Local hash embeddings and in-memory storage were
used, not a live external vector database, production session, or downstream LLM.

The unit/integration mechanism checks live at the named runtime revision:

- `internal/epistemic/evidence_test.go`: conversation/run/time repetition,
  conversation occurrence-flag rejection, source-order canonicalization, explicit
  observed occurrences, timestamp-only repetition, and same-lineage near copies.
- `internal/packing/packing_test.go`: occupancy suppression and distinct
  Anti-Pigeon-key exemption.
- `internal/service/epistemic_test.go`: configuration validation, unchanged
  ordinary update flags, bucket exemption, and selected-feedback rejection while
  preserving full-stream/audit routes under their existing acceptance rules.

These targeted tests were rerun during the September 4 paper synchronization and
passed. They test declared mechanisms, not semantic truth or poisoned-answer
success. The tests do not establish authenticated source independence, a
cross-journal evidence budget, complete duplicate handling within every exempt
bucket, or safety against an attacker who controls feedback issuance.

The aggregate report intentionally has no confidence claim: the gate-specific
comparison was not preregistered, the confirmation-named blocks were reused, and
two sources have zero or one confirmation case. No new paired end-to-end latency
experiment is attached. Earlier packing-only microbenchmarks cannot determine
service-wide overhead or tail latency and are not treated as that evidence.
